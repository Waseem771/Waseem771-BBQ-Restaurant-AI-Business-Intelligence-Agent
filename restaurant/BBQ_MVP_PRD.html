🍖 BBQ Restaurant AI MVP - PRD

1. Executive Summary

An intelligent restaurant analytics platform that allows BBQ restaurant management to ask natural-language questions about their business and receive data-driven insights powered by AI, database queries, and machine learning.

Target User: Restaurant managers, analysts, and owners

Success Metric: Successfully answer 5 key business questions with accurate data + AI reasoning

2. MVP Scope

The MVP will deliver a working end-to-end pipeline for ONE complete user journey:

User Journey:
Manager → Dashboard (see KPIs) → AI Chat (ask question) → SQL Tool (query DB) → LLM (generate response) → Answer

What's IN MVP:

  • ✅ Clean BBQ restaurant dataset (PostgreSQL)
  • ✅ FastAPI backend with core APIs
  • ✅ Simple web dashboard with KPIs & charts
  • ✅ AI assistant with SQL tool calling
  • ✅ Natural language to data insights
  • ✅ Authentication (basic)
  • ✅ Docker setup

What's OUT (Phase 2+):

  • ❌ RAG (knowledge base)
  • ❌ Sales forecasting
  • ❌ Anomaly detection
  • ❌ WebSockets / real-time
  • ❌ Model versioning
  • ❌ Advanced analytics

3. Core Features

3.1 Dashboard

Display:

  • Total Revenue (all-time)
  • Total Orders (all-time)
  • Average Order Value
  • Top 5 Products (by revenue)
  • Daily Sales Chart (last 30 days)
  • Sales by Product Category
  • Order count trend

Tech: React + TypeScript + Recharts

3.2 AI Assistant

Capability: Answer natural language questions by querying the database

Example Q&A:

  • Q: What's our total revenue?
    A: Total revenue is Rs. 2,845,000 across 324 orders.
  • Q: Which products are top sellers?
    A: BBQ Platter (320 units, Rs. 800K), Chicken Wings (215 units, Rs. 430K)...
  • Q: What was revenue on August 20?
    A: Revenue on August 20 was Rs. 125,000 from 18 orders.
  • Q: Which day has highest sales?
    A: Saturday has the highest average daily revenue at Rs. 95,000.

Tech: Claude API + SQL tool

3.3 Agent Architecture (MVP)

User Question ↓ Intent Recognition (Claude) ↓ SQL Tool Selection ↓ Execute Query ↓ Result Analysis ↓ Natural Language Response

4. API Endpoints (MVP)

Dashboard Endpoints

GET /api/v1/dashboard/metrics

Returns: total_revenue, total_orders, avg_order_value, top_products, daily_sales, category_breakdown

Sales Endpoints

GET /api/v1/sales/daily

Query params: start_date, end_date. Returns daily sales

GET /api/v1/sales/total

Returns total revenue across all time

Product Endpoints

GET /api/v1/products/top

Query params: limit (default 10). Returns top products by revenue

GET /api/v1/products

Returns all products with sales metrics

AI Agent Endpoints

POST /api/v1/ai/ask

Body: {"question": "string"}
Returns: {"answer": "string", "data_source": "database|ml|combination", "confidence": 0-1}

Auth Endpoints

POST /api/v1/auth/login

Body: {"username": "string", "password": "string"}
Returns: JWT token

POST /api/v1/auth/register

Create new user (MVP: admin only)

Health Endpoint

GET /api/v1/health

Returns: {"status": "healthy", "database": "connected", "ai_service": "available"}

5. Data Model (PostgreSQL)

Core Tables

Table Purpose Key Columns
products Product catalog id, name, category, price, created_at
orders Order transactions id, date, total_amount, quantity, created_at
order_items Items per order id, order_id, product_id, quantity, unit_price
users App users id, username, email, password_hash, role
sales_daily Daily aggregated sales date, total_revenue, total_orders, avg_order_value

6. AI Tool: SQL Query Tool

Purpose

Enable the AI agent to query the database safely and accurately.

Supported Queries (Whitelisted)

  • Total revenue calculation
  • Product sales ranking
  • Daily/weekly/monthly aggregations
  • Order metrics (count, average)
  • Time-based comparisons
  • Category breakdowns

Safety Rules

  • ✅ SELECT queries only
  • ❌ DELETE, UPDATE, DROP prohibited
  • ❌ No arbitrary SQL execution
  • ❌ No credential exposure
  • Queries logged for audit
